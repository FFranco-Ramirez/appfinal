Objetivo General
Desarrollar un sistema de control de acceso basado en tecnología RFID y
componentes IoT que registre y valide las MAC de dispositivos RFID (tarjetas y
llaveros), gestionado mediante una aplicación móvil y una base de datos en la nube
(AWS).

Criterios de Evaluación

1. Funcionamiento del Prototipo (25 Pts):
o Debe realizar la conexión de los dispositivos de manera funcional
donde se muestre la correcta conexión y funcionamiento del sistema
IOT

2. Diseño e Implementación Técnica (25 Pts):
o Correcta configuración del NodeMCU y los componentes físicos
(aro LED, servo motor, lector RFID).
o Integración con la nube (AWS) para el almacenamiento de datos.

3. Funcionalidad del Sistema (30 Pts):
o Registro y validación de accesos en tiempo real.
o Respuesta adecuada del aro LED y la barrera según el estado de
validación.

4. Desarrollo de la Aplicación Móvil (50 Pts):
o Diseño intuitivo y funcional de la aplicación.
o Correcto manejo de los accesos y visualización del historial.
o Registrar Sensores
o Activar o Desactivar Sensores
o Agregar, Modificar, Eliminar Usuarios


Materiales Requeridos con arduino
• NodeMCU V3: Microcontrolador principal.
• Aro LED de 12 LEDs: Indicador visual.
• Servo Motor: Para la barrera de acceso.
• Lector RFID: Para las tarjetas y llaveros.
• Tarjetas y Llaveros RFID: Dispositivos de identificación.

Requerimiento Funcional de la Solución:
 Múltiples usuarios por departamento: El sistema debe considerar que un
mismo departamento puede tener múltiples usuarios (por ejemplo, varios
residentes). Cada usuario puede tener uno o más sensores asociados
(tarjetas y/o llaveros).
 Rol de administrador por departamento: Por cada departamento debe
existir exactamente un usuario administrador.
Funciones exclusivas del administrador:
o Registrar nuevos sensores asociados al departamento.
o Activar/desactivar sensores.
o Activar/desactivar otros usuarios del mismo departamento (si se
decide).


 Usuarios operadores de aplicación
o Los demás usuarios del departamento tendrán rol de operador:
 Pueden usar sus sensores para ingresar.
 Pueden visualizar el historial de accesos del departamento.
 Pueden usar la app como “llavero digital”
 No pueden agregar, eliminar ni cambiar estados de sensores.
 No pueden cambiar configuraciones del departamento.

Requisitos Técnicos del Sistema
1. Funcionalidades del Sistema:
 Registro de nuevos sensores (tarjetas/llaveros)
Desde la aplicación móvil se debe permitir agregar nuevos sensores RFID
(tarjetas o llaveros) asociados a un departamento y a un usuario
administrador:
o La app debe disponer de una pantalla de “Gestión de Sensores”.
El administrador debe poder ingresar:
 Código único del sensor (MAC / UID RFID).

 Estado inicial del sensor (activo, inactivo, perdido,
bloqueado).
Al guardar, la app debe:
o Enviar la información a la API en AWS.
o Registrar el sensor en la tabla correspondiente (por ejemplo:
sensores).
o Asociar el sensor al departamento y al usuario.

 Activar / desactivar sensores desde la app
o La aplicación móvil debe permitir cambiar el estado de cada sensor
(ej.: activo / inactivo) desde la pantalla de gestión.
o Solo el usuario administrador del departamento puede: Activar o
desactivar un sensor, marcar un sensor como “perdido/bloqueado”.
o El cambio debe reflejarse de inmediato en la BD en AWS para que el
NodeMCU considere el nuevo estado en la validación de acceso.
 Control manual de la barrera desde la App - Apertura y cierre remoto
de barrera
o Abrir (levantar) la barrera manualmente mediante un botón “Abrir
barrera”.
o Cerrar (bajar) la barrera manualmente mediante un botón “Cerrar
barrera”.
La app debe:
o Enviar la acción al backend/API, que a su vez notifica al
microcontrolador (NodeMCU).
o Mostrar el estado actual de la barrera (Abierta / Cerrada).
o Toda apertura/cierre manual debe registrarse como evento de
acceso en la BD.

Registro en la Nube (AWS):
o Debe crear una Instancia donde permita crear su Base de datos.
o Crear una tabla en la base de datos que registre las MAC de las
tarjetas y llaveros válidos.
o Debe crear una tabla para registrar los eventos de acceso
(permitido o denegado) con detalles de fecha, hora y dispositivo.
o Debe crear las API para insertar y consultar los datos necesarios.

 Validación de Acceso:
o Si el llavero o Tarjeta RFID es válido:
o El aro LED debe encenderse en color verde.
o El servo motor debe levantar la barrera de acceso.
o Después de 10 segundos, la barrera debe volver a bajar
automáticamente.
o Debe registrar la fecha y hora del acceso
o En la Aplicación Móvil se debe visualizar inmediatamente el
evento ocurrido.
o Si una llavero o Tarjeta RFID no tiene acceso:
o El aro LED debe encenderse en color rojo.
o Registrar el evento en la base de datos en la nube fecha y hora.
o En la Aplicación Móvil se debe visualizar inmediatamente el
evento ocurrido.

 Gestión desde la Aplicación Móvil:
o Mostrar el estado en tiempo real de los accesos. (Valido - Fallido)
Identificar quién intenta ingresar y mostrar las opciones:
 Permitir Acceso: Al presionar un botón, el aro LED debe
encenderse en verde y el servo motor debe levantar la
barrera.
 Denegar Acceso: Mantener el aro LED en rojo y no activar la
barrera.
